# jigane 0.1.6 のお知らせ

0.1.6 では、`jigane run` を始めるまでの待ち時間を短くしました。同意の確認は実行する群だけを見積もり、方針の群は見積もりと実行で同じ組み立てを繰り返さなくなりました。`jigane estimate` の出力、コマンドの引数、保存物の形式は変えていません。

## 変えたこと

| No. | 対象 | 変えたこと | 関わる質問 |
| --- | --- | --- | --- |
| 1 | `jigane run` の同意の確認 | 実行する群だけを見積もります。他の群の内訳と和の行は出なくなりました。 | [同意の確認は、どう変わりましたか](#同意の確認はどう変わりましたか) |
| 2 | 実装とセキュリティの群の `jigane run` | 方針の群の見積もりを待たなくなりました。 | [どれくらい速くなりましたか](#どれくらい速くなりましたか) |
| 3 | 方針の群の見積もりと実行 | 同じ組み立てを一回のコマンドの中で繰り返さなくなりました。 | [どれくらい速くなりましたか](#どれくらい速くなりましたか) |
| 4 | Claude Code のプロセスの環境 | 文法を読まない実行では、利用者名を含む文法の置き場のパスを置かなくなりました。 | [Claude Code のプロセスに置くものは、どう変わりましたか](#claude-code-のプロセスに置くものはどう変わりましたか) |

## 想定される質問

### 更新の後に、必要な操作はありますか

通常はありません。保存物の形式、Claude Code の下限（2.1.308）、文法の版は変えていないので、0.1.5 までのレビューはそのまま続けられ、`jigane languages fetch` のやり直しも通常は要りません。

### 同意の確認は、どう変わりましたか

実行する群の内訳だけが出ます。検証役の有無と前回の実績は、この内訳の中に出ます。他の群の額は見積もらず、次の一行で確かめ方を示します。

> 他の群の額は見積もっていません。`jigane estimate <レビュー> <群>` で確かめられます。

### どれくらい速くなりましたか

実装とセキュリティの群では、方針の群の見積もりを待たなくなりました。短くなる時間は測っていません。

方針の群では、`jigane estimate macro` と `jigane run macro` の準備が短くなります。偽の `claude` を使い、jigane 自身の 43 ファイルの範囲で 2 回ずつ測った目安は次のとおりです。ほかの作業と CPU を分け合う状態で測ったので、環境によって変わります。前の値は No.1 を入れた後の開発中の版のもので、0.1.5 では `jigane run macro` がさらに他の群も見積もっていました。

| 計測した対象 | No.3 の前 | No.3 の後 |
| --- | --- | --- |
| `jigane estimate macro` | 31.5 秒 | 20.2 秒 |
| `jigane run macro` の最初の起動まで | 54.5 秒 | 20.4 秒 |

繰り返さないのは一回のコマンドの中だけです。`jigane estimate` の後に `jigane run` を走らせると、組み立てはそれぞれで行われます。

### Claude Code のプロセスに置くものは、どう変わりましたか

文法の置き場のパス（`TREE_SITTER_LANGUAGE_PACK_CACHE_DIR`、利用者名を含む絶対パス）は、jigane がその実行の中で文法を読んだときだけ、Claude Code のプロセスの環境に置かれます。モデルへは渡りません。0.1.5 までは、実装とセキュリティの群でも同意の確認の見積もりで文法を読むことがあり、そのときはこのパスが置かれていました。0.1.6 でも、変更に正規表現の札を読む言語のソースがあれば文法を読み、パスは置かれます。どの入力がどの群に渡るかは、[SECURITY.md](../../SECURITY.md) の表に書いています。
