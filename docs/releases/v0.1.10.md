# jigane 0.1.10 のお知らせ

0.1.10 は、不具合修正だけのバージョンです。機能追加と仕様変更はありません。変更は、続く「変えたこと」の表にあります。

## 不具合修正

0.1.9 で、PR のレビューを作るときと `jigane refresh` で PR のレビューを更新するときに、ファイルの展開が極端に遅くなることがありました。これを直しました。

更新するだけでよく、操作は要りません。

## 変えたこと

| No. | 対象 | 変えたこと | 関わる質問 |
| --- | --- | --- | --- |
| 1 | PR のレビューのファイルの展開 | `jigane new pr` と PR のレビューの `jigane refresh` で、手元に無いファイルの中身を、1 回の `git fetch` でまとめて取ります。 | [PR のレビューで、ファイルの展開が遅くなったのは、なぜですか](#pr-のレビューでファイルの展開が遅くなったのはなぜですか) |

## 想定される質問

### PR のレビューで、ファイルの展開が遅くなったのは、なぜですか

jigane は、PR のレビューのために、レビュー対象のリポジトリを、ファイルの中身（ブロブ）を落とさない形（`--filter=blob:none`）でクローンしています。中身は、必要になったときに取りに行きます。

0.1.9 は、セキュリティの対策として、PR の変更前と変更後のファイルの展開を `git archive` から `git ls-tree` と `git cat-file --batch` に変えました。

`git cat-file --batch` は、手元に無いファイルの中身を、1 件ずつネットワークから取りに行きます。そのため、ファイルの数だけ `git fetch` が起動していました。

1,726 ファイルのリポジトリでは、10 分たっても展開が終わりませんでした。

0.1.10 は、展開の前に、手元に無いファイルの中身の一覧を作り、1 回の `git fetch` でまとめて取ります。手元に無い中身が無いときは、`git fetch` を起動しません。

同じリポジトリを手元で測ると、展開は 1.93 秒で終わりました。測ったのは 1 回だけで、時間は、リポジトリの大きさと通信の状況で変わります。

0.1.9 のセキュリティの対策は、変えていません。jigane が git を起動する共通の入口を通ることと、ファイルの中身をバイト列のまま読むことは、そのままです。

更新するだけでよく、操作は要りません。更新の方法は、入れた方法で決まります。

`uv tool install jigane` で入れた場合：

```bash
uv tool upgrade jigane
```

`pipx install jigane` で入れた場合：

```bash
pipx upgrade jigane
```
