# jigane 0.1.13 のお知らせ

0.1.13 の変更を機能追加、仕様変更、不具合修正に分け、個々の内容を「変えたこと」の表にまとめました。

## 機能追加

該当項目はありません。

## 仕様変更

Codex の `jigane estimate --json` から、`max_prompt_bytes` と `exceeds_prompt_limit` を削除しました。この 2 つのフィールドを参照するスクリプトは、更新時に参照を外してください。

jigane は、レビューに渡す一部のファイルを読み取るときに、シンボリックリンクを検査するようにしました。

セキュリティの方針に、Claude Code と Codex がレビュー資料内の文を指示として扱うおそれを追記しました。

レビューのプロンプトでは、過去の指摘や図から抜き出した情報の一部を Markdown のコードブロックで囲むようにしました。

## 不具合修正

Codex のレビューで、jigane がプロンプトを送る前に適用していた 32 KiB の上限を撤去しました。

## 想定される質問

### なぜ長い設計書のレビューが止まっていたのですか

0.1.12 では、Codex に渡すプロンプトが 32 KiB を超えると、jigane が送信前にレビューを止めていました。設計書のレビューでは、設計書の全文を含む資料を送るため、この上限に達することがありました。

最初に送る各プロンプトの UTF-8 のバイト数は、`jigane estimate <レビュー> <群> --json` の `prompt_bytes` で確認できます。

### 見積もりを読むスクリプトはどう変えますか

削除した 2 つのフィールドは、上限のバイト数と、プロンプトがその上限を超えたかを示していました。スクリプトからは両方の参照を外してください。

Codex の `noninteractive_run_available` は、MCP を指定せず、群の費用を見積もれたときに `true` になります。起動前には別途ログイン状態を確認し、見積もりを指定額と照合します。[非対話実行の条件](../commands.md#jigane-debug)

### シンボリックリンクを指定するとどうなりますか

リンク先の本文が意図せずレビュー資料に入るのを防ぐため、対象の読み取りにシンボリックリンクの検査を加えました。

`--intent-file` と `--mcp-guide` の読み取りでシンボリックリンクを検出すると、エラーで止まります。設定した開発方針やセキュリティ指針を読めない場合は、標準エラーに警告を出し、その文書を除いてレビューを続けます。

この検査でエラーや警告が出た場合は、該当する入力に通常のファイルを指定してください。

### レビュー結果をどう確かめればよいですか

レビュー資料に紛れ込ませた文をモデルへの指示として扱わせる手法を、**プロンプトインジェクション**と呼びます。Claude Code と Codex のどちらでも、モデルが問題を見逃したり、実際にはない問題を指摘したりすることがあります。

信頼できない PR の本文や、レビューに含まれるボットのコメントは、指摘が 0 件でも自分で確かめてください。

モデルが使える機能の制限とシンボリックリンクの既知の限界も参照してください。[セキュリティの方針](../../SECURITY.md)

### なぜレビュー資料をコードブロックで囲むのですか

Markdown 上でレビュー資料の範囲を明示し、モデルへの指示と区別するためです。コードブロックの区切りには、資料の本文に含まれるどのバッククォートの並びよりも長い並びを使います。
