## 参照の体系

担当のファイルごとに、モバイルアプリのコードかバックエンドのコードかを判断し、体系を選んでください。言語では判断できません（Java と C# はどちらにも現れます）。

- モバイルアプリのコード（Android、iOS、モバイル向けの共有コード）: MASVS の管理策、MASWE の弱点、MASTG のテストを参照します。
- バックエンドのコード（サーバ、API、サーバ上で動くプラグイン）: OWASP ASVS、WSTG、Cheat Sheet Series、API Security Top 10、Proactive Controls、Top 10 を参照します。

## 観点

各指摘の viewpoint には、次のいずれかを入れます。

モバイルアプリのコードは MASVS の群に従います。

- S-STORAGE データの保存。
- S-CRYPTO 暗号。
- S-AUTH 認証と認可。
- S-NETWORK 通信。
- S-PLATFORM プラットフォームとの相互作用（IPC、WebView、権限）。
- S-CODE コードの品質と、ビルドの設定。
- S-RESILIENCE 耐性（改ざん、リバースエンジニアリングへの備え）。
- S-PRIVACY プライバシー。

バックエンドのコードは ASVS の章に従います。`S-ASVS-V<章の番号>` の形で、章の番号は 1 から 17 です（例: S-ASVS-V6）。章は、ASVS 5.0 の章立てに合わせます。

## 書き方

- 最初に、担当のファイルごとに、信頼できない入力（利用者、ネットワーク、レビュー対象のデータ）、資格情報と秘密、外部への出力（ファイル、プロセス、ネットワーク、画面）を書き出します。次に、それぞれについて該当する体系の項目を確かめ、本文を読んでから、コードがその項目を満たしているかを判断します。確かめを一度で済ませず、扱う論点ごとに行ってください。
- 担当のシャードの中身を、一行ずつ網羅的に読んでください。拾う範囲は網羅的にし、断定は、読んだ内容から確かめられた範囲に限ります。設定ファイルの挙動を述べるときは、中身に添えた冒頭の設定を先に確かめます。
- 担当のシャードに無いファイルは、別のシャードが読みます。担当の外のファイルは、文脈を確かめるためにだけ Read、Grep、Glob で読み、その位置だけを根拠にした指摘は出さないでください。evidence には、担当のファイルの位置を少なくとも一つ入れます。
- 差分レビュー式では、差分は変更の位置と前後 3 行しか含みません。呼び出し元や定義など、判断に要る文脈は作業ディレクトリから読んでください。
- claim には主張を一文で書きます。body には、何が起きているか、どの入力や状態で悪用できるか、どちらの方向に直すかを書きます。直し方は方向を示すにとどめます。
- evidence には、判断の根拠にしたコードまたは設定の位置（作業ディレクトリからの相対パスと、行の範囲）を一つ以上入れます。根拠の位置を示せない指摘は出さないでください。
- declaration_ref と judgment_region は null にします。
- severity は次のとおりです。critical は、読んだ内容から確かめられた悪用できる欠陥。warning は、対応を要する問題と、確認を求める懸念。nit は、任意の提案。

- 指摘が無ければ、findings を空の配列にしてください。
